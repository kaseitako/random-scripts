# Startup Virtual Desktop Store ショートカット対応設計

## 目的

Microsoft Store アプリなどのシェルショートカットを起動した場合でも、対象ウィンドウを待機・検出し、定義された仮想デスクトップへ移動して配置を検証できるようにする。今回確認された Spotify の起動エラーと配置漏れを解消しつつ、通常の実行ファイルと通常のショートカットの動作は維持する。

## 確認できた原因

- 最新ログでは Spotify だけが `Failed` となり、ハンドルは `0`、経過時間は `43ms` だった。
- `C:\Spotify.lnk` は存在するが、`WScript.Shell.CreateShortcut()` で取得した `TargetPath` は空だった。
- この種類のショートカットへ `Start-Process -PassThru` を指定すると、起動処理からプロセス情報を取得できず例外になる。
- 現行処理は例外を受けた時点で終了するため、後段のウィンドウ待機・移動・配置検証へ進まない。
- 実際の Spotify ウィンドウはプロセス名 `Spotify`、タイトル `Spotify Premium` として取得できる。

## 変更方針

### ショートカットの分類

Windows アダプター内に、ショートカットの対象パスと表示名を取得する内部ヘルパーを設ける。

- `TargetPath` が取得できる通常ショートカットは、従来どおり起動したプロセスを追跡する。
- `TargetPath` が空のシェルショートカットは、起動したプロセスを直接追跡しない。
- ショートカット以外の実行ファイルやコマンドは、従来どおり起動したプロセスを追跡する。

解決済みアプリケーション情報へ内部フラグ `trackStartedProcess` を追加し、分類結果を起動処理へ渡す。このフラグは内部情報であり、JSON設定の新しい項目にはしない。

### 起動処理

`Start-DesktopApplication` は `trackStartedProcess` が偽の場合に限り `Start-Process` へ `-PassThru` を渡さない。起動要求が正常に受け付けられたら `ProcessId = 0` を返し、既存のウィンドウポーリングを継続する。

`trackStartedProcess` が真、または古い呼び出し元からプロパティが渡されなかった場合は、互換性のため従来どおり `-PassThru` を使用してプロセスIDを返す。

### ウィンドウの特定と配置

シェルショートカットでは起動プロセスIDを利用できないため、既存の `windowMatch` と起動前後のウィンドウ差分を使って対象を特定する。対象ウィンドウが見つかった後の移動、配置検証、最大化、ログ出力は変更しない。

個人設定の Spotify へ次の明示条件を追加する。

```json
"windowMatch": {
  "processName": "Spotify",
  "titleRegex": "Spotify"
}
```

これにより、ショートカット名や空の対象パスからプロセス名を推測せず、実ウィンドウの情報で Spotify を識別する。個人パスを含む `virtual-desktop-setting.json` はコミット対象に含めず、ローカル変更として保持する。

## エラー処理とログ

- シェルショートカット自体の起動要求が失敗した場合は、従来どおりアプリケーション結果を `Failed` とする。
- 起動要求後に一致するウィンドウが現れない場合は、既存のタイムアウトと診断ログを使用する。
- `ProcessId = 0` は「プロセス情報を取得しない起動」を表し、失敗とはみなさない。
- ログ形式、終了コード、ほかのアプリケーションを継続処理する挙動は変更しない。

## テスト

- 通常ショートカットが `trackStartedProcess = true` に分類されることを確認する。
- 対象パスが空のショートカット情報をテスト用に再現し、`trackStartedProcess = false` に分類されることを確認する。
- 追跡する起動では `Start-Process -PassThru` が使われ、取得したプロセスIDを返すことを確認する。
- 追跡しない起動では `-PassThru` が使われず、例外なく `ProcessId = 0` を返すことを確認する。
- 既存の全Pesterテスト、PowerShell構文検証、JSON解析、設定スキーマ検証を実行する。
- 実環境の Spotify による最終確認は、修正後にスクリプトを再実行し、ログが `Moved` または `AlreadyPlaced` となること、および「音楽」デスクトップへ配置されることを確認する。

## 変更しないもの

- デスクトップの名前、順序、壁紙
- アプリケーションの起動順序と Spotify のショートカットパス
- 通常の実行ファイルと対象パスを取得できるショートカットのプロセス追跡
- ウィンドウ待機、移動、配置検証のアルゴリズム
- 公開設定スキーマとサンプル設定
