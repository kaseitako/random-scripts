# Startup Virtual Desktop ウィンドウハンドル再取得設計

## 目的

アプリケーションの起動中にトップレベルウィンドウが差し替わっても、最新のウィンドウを再取得し、定義された仮想デスクトップへの移動と配置検証を完了できるようにする。今回確認されたLINEの `TYPE_E_ELEMENTNOTFOUND` を解消し、同じ起動方式を持つほかのアプリケーションにも適用できる汎用的な回復処理とする。

## 確認できた原因

- 再起動時ログでは、LINEのウィンドウとしてハンドル `198166` を選択した後、`Test-Window` 内部の `HasWindow` が `TYPE_E_ELEMENTNOTFOUND` を返した。
- 調査時点では同じLINEプロセスのメインウィンドウがハンドル `198412` に変わっていた。
- 古い `198166` へ `Test-Window` を実行すると同じ例外を再現し、現在の `198412` は「メイン」デスクトップに対して `True` を返した。
- 現行処理はウィンドウを選択した直後にハンドルを予約し、その後は再列挙しないため、選択から配置検証までの間に差し替わると回復できない。

## 検討した方式

| 方式 | 利点 | 欠点 | 判断 |
|---|---|---|---|
| 現状維持して発生頻度を観察 | コード変更がない | 再起動時の失敗・非ゼロ終了が残り、配置保証がない | 不採用 |
| LINEの前へ固定スリープを追加 | 実装量が少ない | 全体が遅くなり、時間依存で、ほかのアプリへ効かない | 不採用 |
| 配置時に最新ハンドルを再確認・再取得 | 待ちを失敗時だけに限定でき、ほかのアプリにも有効 | 小さな再試行制御とテストが必要 | 採用 |

## 変更方針

### 最新ウィンドウの選択

`StartupVirtualDesktop.Core.psm1` に、選択済みウィンドウを現在のウィンドウ一覧と照合する内部ヘルパーを追加する。

1. 選択済みハンドルが現在も存在し、プロセスIDも選択時と同じ場合は、現在の列挙結果に含まれる同じハンドルの情報を返す。
2. ハンドルが消えている、または別プロセスへ再利用されている場合は、古いハンドルを予約済み集合から削除する。
3. 現在のウィンドウ一覧に対して既存の `Get-BestApplicationWindow` を使い、同じ `windowMatch` または推測条件に一致する代替ウィンドウを選ぶ。
4. 代替ウィンドウが見つかった場合は、その新しいハンドルを予約して返す。
5. 一致するウィンドウがまだない場合は `$null` を返す。

ウィンドウ照合規則は新設せず、既存のスコアリング、明示的な `windowMatch`、ハンドル重複防止をそのまま利用する。

### 配置の再試行

`onExisting = Skip` 以外のアプリケーションについて、選択後の配置処理を最大5回のループにする。各試行では次を行う。

1. 現在のトップレベルウィンドウ一覧を取得し、選択済みウィンドウを最新状態へ更新する。
2. 一致するウィンドウがなければ、最終試行を除いてアダプターの `Wait` で200ms待ち、次の試行へ進む。
3. 最新ウィンドウで `TestWindow` を実行する。
4. 対象デスクトップにない場合は `MoveWindow` を実行し、再度 `TestWindow` で配置を検証する。
5. `TestWindow` または `MoveWindow` が例外を返した場合は、最終試行を除いて200ms待ち、次の試行でハンドルを再列挙する。

待機はハンドル消失または配置APIの失敗時だけ発生し、最大でも4回、合計800msとする。通常のアプリケーションへ固定待機は追加しない。アプリケーションの再起動は行わず、重複プロセスを防ぐ。

### 結果とログ

- 回復に成功した場合は、最終的に使用した新しいハンドルを結果とJSONLログへ記録する。
- 既に対象デスクトップにあれば `AlreadyPlaced`、移動・検証した場合は `Moved` とする。
- ハンドルが変わった場合は、古いハンドル、新しいハンドル、試行回数を診断ログへ `Warning` として記録する。
- 5回の試行で一致するウィンドウが現れない場合は `Failed` とし、最後の配置APIエラー、またはウィンドウ消失を示すエラーを記録する。
- 1アプリの最終失敗後も、既存どおり後続アプリケーションの処理を継続する。

### 最大化

`maximized = true` の処理は、移動と配置検証が成功した後に1回だけ実行する。最大化のために配置ループを増やさず、既存の失敗処理を維持する。

## テスト

- 選択済みハンドルが有効な通常ケースで、余分な待機なしに従来どおり配置できることを確認する。
- 最初の `TestWindow` で古いハンドルが例外になり、次の列挙で同じアプリケーションの新しいハンドルが現れた場合に、再取得・移動・検証が成功することを確認する。
- ハンドル差し替え後の結果へ新しいハンドルが記録され、古いハンドルが後続アプリケーションを妨げないことを確認する。
- 代替ウィンドウが現れない場合に5回で停止し、`Failed` を返し、後続アプリケーションを処理することを確認する。
- 配置検証が恒常的に失敗する既存テストが引き続き `Failed` となることを確認する。
- 全Pesterテスト、PowerShell構文検証、設定検証、Git差分検証を実行する。

## 変更しないもの

- JSON設定スキーマ、個人設定、デスクトップ構成
- アプリケーションの起動順序、起動回数、ウィンドウ照合条件
- `timeoutSeconds`、`onExisting`、移動後の最大化の意味
- WindowsアダプターとVirtualDesktopモジュールの公開インターフェース
- 既存のサマリー形式と終了コード規則

## 受け入れ条件

- LINEが起動中にハンドルを差し替えても、新しいウィンドウが「メイン」デスクトップへ配置・検証される。
- 成功ログのLINEハンドルは、最終的に検証された現在のハンドルである。
- 通常ケースの処理時間へ固定待機を追加しない。
- 再取得処理は最大5回で終了し、無限ループしない。
- 自動テストが実ウィンドウや仮想デスクトップを変更せずに回帰を再現する。
